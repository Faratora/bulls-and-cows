# Bulls and Cows — DESIGN.md

## 1. Цель документа

Описание архитектуры, структур данных, алгоритмов и их сложности для игры
«Быки и коровы». Игровое ядро — чистые функции без DOM; ввод-вывод
(рендер, таймер, `localStorage`) изолирован в слое `src/ui`.

## 2. Модульная архитектура

```
src/
├── game/          # чистое ядро: никаких импортов DOM
│   ├── types.ts         # все типы данных
│   ├── digits.ts        # каррированный валидатор цифры по основанию
│   ├── guess.ts         # isValidGuess: длина + алфавит + уникальность
│   ├── score.ts         # evaluateGuess: быки и коровы
│   ├── secret.ts        # generateSecret: случайный секрет с инъекцией случайности
│   ├── count.ts         # countPossibleSecrets: рекурсия + мемоизация
│   ├── state.ts         # иммутабельные переходы состояния раунда
│   └── leaderboard.ts   # чистая сортировка и обрезка таблицы рекордов
├── ui/            # DOM-слой: только построение узлов и подписки
│   ├── settings.ts      # экран настроек
│   ├── play.ts          # экран игры
│   ├── win.ts           # экран победы
│   ├── leaderboard.ts   # экран таблицы рекордов
│   ├── leaderboard-storage.ts   # адаптер localStorage
├── utils/
│   └── memoize.ts       # самописная мемоизация функции двух аргументов
└── main.ts         # контроллер: владелец ссылки state и интервала таймера
```

Зависимости направлены строго вниз: `ui → game → (digits, types)`.
Ядро тестируется без DOM; слой UI — тонкая обёртка над чистыми функциями.

## 3. Структуры данных

Все структуры объявлены в `src/game/types.ts` как `readonly`-типы.

| Тип                 | Поля                                                                    | Инварианты                                                                          |
| ------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `NumericBase`       | `2 \| 8 \| 10 \| 16`                                                    | основание системы счисления                                                         |
| `SecretLength`      | `2..6`                                                                  | длина секрета и попытки                                                             |
| `Secret`            | `string`                                                                | `length` уникальных цифр алфавита base; **строка, а не число** — ведущий `0` значим |
| `Guess`             | `string`                                                                | та же форма, проверяется `isValidGuess`                                             |
| `Score`             | `bulls: number; cows: number`                                           | `bulls + cows ≤ length`                                                             |
| `HistoryEntry`      | `guess: Guess; score: Score`                                            | неизменяемая запись попытки                                                         |
| `GameSettings`      | `length: SecretLength; base: NumericBase`                               | `length ≤ base`, иначе 0 возможных секретов                                         |
| `GameState`         | `phase, settings, secret, history, startedAt, firstGuessAt, finishedAt` | `phase ∈ 'settings' \| 'playing' \| 'won'`                                          |
| `LeaderboardRecord` | `length, base, attempts, elapsedMs, finishedAt`                         | сортировка в `leaderboard.ts`                                                       |

### Ключевое решение: секрет — строка, а не число

`generateSecret` возвращает `string`. Числовое представление потеряло бы
ведущий ноль (`'0123'` → `123`) и потребовало бы паддинга при сравнении.
Строка цифр делает `evaluateGuess` и сравнение попыток тривиальными.

### Иммутабельность состояния

`GameState` никогда не мутируется. Каждый переход (`startRound`,
`recordGuess`, `backToSettings` в `state.ts`) строит новый объект через
spread и литералы массивов:

```ts
const history = [...state.history, entry];
return { ...state, history, phase: won ? 'won' : state.phase };
```

Единственная мутируемая ссылка в приложении — локальная переменная `state`
в контроллере `src/main.ts`; React-подобный цикл «состояние → рендер».

## 4. Алгоритмы

### 4.1. `createDigitValidator(base)` — `src/game/digits.ts`

Каррированная фабрика: `createDigitValidator(base)(char) → boolean`.
Общий алфавит `'0123456789abcdef'`; позиция символа в алфавите должна быть
строго меньше `base`. Регистр нормализуется `toLowerCase()` — hex-цифры
`A–F` эквивалентны `a–f`. Многосимвольный ввод отвергается.

### 4.2. `isValidGuess(guess, length, base)` — `src/game/guess.ts`

Три условия, соединённые `&&`:

1. `digits.length === length` — точная длина;
2. `digits.every(createDigitValidator(base))` — алфавит основания;
3. `new Set(digits).size === digits.length` — уникальность цифр
   (регистронезависимо, поэтому `Aa` в hex — повтор).

### 4.3. `evaluateGuess(secret, guess)` — `src/game/score.ts`

Обе строки нормализуются к нижнему регистру и разбиваются на массивы цифр.

- **Быки** — свёртка (`reduce`) по позициям: совпадение цифры и позиции.
- **Коровы** — количество общих цифр (поиск через `Set`) минус быки:
  каждая позиция учитывается не более одного раза, поэтому
  `secret='0123'`, `guess='0321'` даёт `{bulls: 2, cows: 2}`.

Чистая функция: аргументы не мутируются, возвращается новый объект `Score`.

### 4.4. `generateSecret(length, base, random = Math.random)` — `src/game/secret.ts`

Выбор без возвращения (permutation sampling):

1. `buildAlphabet(base)` — алфавит основания как неизменяемый массив цифр.
2. Рекурсивный `pickDigits(pool, length, random)`:
   - база рекурсии: `pool` пуст или длина достигнута → собранный список;
   - шаг: индекс `i = Math.floor(random() * pool.length)`,
     выбранная цифра добавляется к результату, рекурсия продолжается
     по `pool` без этой цифры.

Случайность инъецируется параметром (`RandomSource = () => number`),
что делает функцию детерминируемой в тестах: `() => 0` даёт `'0123'`,
а `Math.random` вызывается ровно `length` раз.

### 4.5. `countPossibleSecrets(length, base)` — `src/game/count.ts`

Число размещений без повторений `P(base, length) = base! / (base − length)!`
вычисляется по рекуррентной связи:

```
P(base, 0)          = 1
P(base, length)     = 0                     при length > base
P(base, length)     = base · P(base−1, length−1)
```

Ведущий ноль разрешён, поэтому ничего не вычитается: для длины 4 и
основания 10 ответ 5040, а не 4536. Рекурсия обёрнута в самописную
`memoize2` (`src/utils/memoize.ts`): кэш `Map<string, number>` с ключом
`length|base` в замыкании фабрики. Повторный вызов не трогает внутреннюю
функцию — проверяется инъекцией счётчика вызовов в тестах.

### 4.6. Переходы состояния — `src/game/state.ts`

- `startRound(settings, random, startedAt)` — копия настроек,
  `generateSecret`, timestamp старта.
- `recordGuess(state, guess, now)` — новая запись истории в свежем
  массиве; при первом ходе фиксируется `firstGuessAt` (время старта
  таймера); при `bulls === length` фаза переключается в `'won'` и
  фиксируется `finishedAt`. Дубликаты и попытки после победы возвращают
  тот же объект состояния — переходов нет.
- `attemptsOf` = `history.length`; `elapsedOf` начинается с нулевого
  времени до первого хода и растёт от `firstGuessAt`, замирая на
  `finishedAt`.

### 4.7. Таблица рекордов — `src/game/leaderboard.ts`

Чистая логика: `isBetterRecord` (меньше попыток, при равенстве — меньше
времени), стабильная `sortRecords` без мутации входа, `addRecord`
(добавить → отсортировать → обрезать до `TOP_SIZE = 10`, вытесняются
худшие, а не старые). Персистентность — адаптер
`src/ui/leaderboard-storage.ts`: один общий ключ `bulls-and-cows:top`,
перенос (миграция) из старых ключей при первом запуске, защита от
битого JSON деградацией в пустой список. Каждая запись содержит бейдж
настроек (`base · length`), который отображается в строке таблицы.

## 5. Сложность (Big O)

`L` — длина секрета, `B` — основание, `H` — размер истории.

| Функция                     | Файл             | Сложность                               | Обоснование                                                                |
| --------------------------- | ---------------- | --------------------------------------- | -------------------------------------------------------------------------- |
| `createDigitValidator`      | `digits.ts`      | **O(1)** на вызов                       | `indexOf` по 16-символьной константе, фиксированная граница                |
| `isValidGuess`              | `guess.ts`       | **O(L)**                                | один проход `every` + построение `Set` из L элементов                      |
| `evaluateGuess`             | `score.ts`       | **O(L)**                                | `reduce` по позициям + `Set` из L цифр: обе фазы линейны                   |
| `generateSecret`            | `secret.ts`      | **O(L·B)**                              | L шагов рекурсии, каждый — `filter` пула ≤ B цифр; для L ≤ 6 это константа |
| `countPossibleSecrets`      | `count.ts`       | **O(L)** первый вызов, **O(1)** из кэша | рекурсия глубиной L; `memoize2` сводит повторные вызовы к lookup `Map`     |
| `recordGuess`               | `state.ts`       | **O(H)**                                | копия истории + проверка дубликата `some` по истории                       |
| `sortRecords` / `addRecord` | `leaderboard.ts` | **O(N log N)**                          | сортировка ≤ `TOP_SIZE + 1` записей, N ≤ 11 — практически константа        |

Максимальные размеры: `L ≤ 6`, `B ≤ 16`, поэтому все «линейные»
оценки фактически константны — ядро не имеет узких мест производительности.

## 6. Принципы чистого кода

| Принцип                                | Где реализован                                                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Чистые функции**                     | всё ядро `src/game`: `evaluateGuess`, `generateSecret`, `countPossibleSecrets`, переходы `state.ts` не читают и не пишут глобальное состояние     |
| **Иммутабельность**                    | `GameState`, `HistoryEntry`, `LeaderboardRecord` — только `readonly`; переходы через spread (`recordGuess`, `backToSettings`)                     |
| **Внедрение зависимостей**             | `RandomSource` в `generateSecret`/`startRound`; таймер передаётся аргументом `now` в `recordGuess`/`elapsedOf` — ядро тестируемо без мока модулей |
| **Каррирование и фабрики**             | `createDigitValidator(base)`, `createCountPossibleSecrets`, `memoize2` — переиспользование частично применённых функций                           |
| **Методы массивов вместо циклов**      | `every`, `reduce`, `some`, `filter`, `map` по всему ядру; явных `for` нет                                                                         |
| **Разделение слоёв**                   | `game/` не знает про DOM; `ui/` не содержит игровой логики — только построение узлов и колбэки                                                    |
| **Именованные константы**              | `DIGIT_ALPHABET`, `TOP_SIZE`, `LENGTH_OPTIONS`, `BASE_LABELS` — никакой «магии» в тексте                                                          |
| **Один уровень абстракции на функцию** | `isValidGuess` композиция из трёх маленьких предикатов; `recordGuess` — один переход за вызов                                                     |
| **Тестируемость**                      | 137 юнит-тестов: детерминизм через инъекцию `RandomSource`, счётчик вызовов для мемоизации, проверки отсутствия мутаций аргументов                |

## 7. Следствия для расширяемости

- Новое основание (например, base 36) — одна правка в `types.ts`
  и строке алфавита; вся логика цифр параметрична.
- Новая метрика рекордов — правка `isBetterRecord`; сортировка и
  обрезка останутся нетронутыми.
- Смена UI-фреймворка не затрагивает `src/game`: ядро — чистые
  функции, пригодные для любого рендерера.
